# Consolidation notes

This plugin began as a consolidation of the forks of
[Quorafind/Obsidian-Float-Search](https://github.com/Quorafind/Obsidian-Float-Search)
(Floating Search) and was later narrowed to one job: open a floating search and open
the file that matches. This file records **where the code came from**, **what was
removed**, and **the fixes that still apply**, so the history does not have to be
reverse engineered from the commits. Keep it up to date when changing any of them.

The `CHANGELOG.md` is generated by release-please; this file is the human-written
provenance record.

## What remains, and from whom

Measured when the plugin was renamed Search & Open: each non-trivial source line
(`src/*.ts`, `styles.css`, ignoring whitespace and trailing punctuation) was matched
against the final upstream, AiurArtanis and Peingxious versions in the repository
history, in that order. About 1,380 lines were counted:

| Origin | Share | What it is |
|---|---|---|
| Upstream (Quorafind, latest) | 55% | The modal, the embedded search view and preview, key handling, Obsidian typings, most of the old `leafView.ts` (itself derived from hover-editor), most of the CSS |
| Written or reworked here | 36% | Settings, the plugin entry, `latestQueue.ts`, the lifecycle and caret handling, the rewritten tests |
| AiurArtanis | 8% | The typed `strings()` and zh-CN translation, the IME guard, parts of the modal and CSS; the regression test harness (`tests/harness.cjs`, about 95% theirs) |
| Peingxious | 1% | Applying the patches on first use (the highlight crash guard was since removed) |

A line counts as "written here" when it is not found verbatim, so reformatting and
renamed identifiers push the share up; treat the numbers as a rough guide, not an audit.
Since then `leafView.ts` was cut from 627 to about 90 lines, the typings from 299 to
about 70, and the harness was trimmed, so the upstream share has dropped further.

Measured again later, against upstream 4.4.1 only (the two other forks were not
included, so it is a lower bound on inherited code): about 870 non-trivial lines in
`src/*.ts` (tests excluded) and `styles.css`, of which 228 (26%) appear verbatim in
upstream. Upstream itself is about 3,800 lines of `.ts` and `.css`, so roughly a tenth
of it survives.

| File | Lines found in upstream |
|---|---|
| `nativeModal.ts` | 20% (70 of 357) |
| `main.ts` | 38% (78 of 204) |
| `leafView.ts` | 33% (18 of 55) |
| `settings.ts`, `settingsTab.ts` | 29% |
| `styles.css` | 51% (35 of 68) |
| `i18n.ts`, `latestQueue.ts`, `matchHighlight.ts` | about 0% (new here) |

The same caveat applies: reformatting and renamed identifiers count as new code, so
the true share is somewhat higher. What is left of upstream is the architecture (one
modal wrapping Obsidian's search view, an embedded preview leaf, the `obsidian://fs`
handler, the key handling) more than the text. This is a derivative with its own
scope, tests and release pipeline rather than a fork that tracks upstream, and it
cannot be merged back as a pull request.

Hover Editor's code reaches this repository through Floating Search: `leafView.ts`
and the `getRoot` patch in `main.ts` are its code (the patch verified against its
`main.ts`). Its recent-files hook, also inherited, was removed: it patched a method
that Obsidian no longer has.

## Features and where they came from

| Feature | Source | Status |

Not taken:

- [smilingpoplar/Obsidian-Float-Search](https://github.com/smilingpoplar/Obsidian-Float-Search):
  its scroll-to-top change is superseded by upstream's preview scroll-to-position,
  and its URI fix deletes `.suggestion-container` from the DOM after a 10ms timer.
- Rebranding (plugin id `float-search-window`, version numbers 1.x / 4.4-4.8) from
  the two forks. This plugin has its own id and starts its own version line at 0.1.0.
- Agent notes, a stray temp file and `package-lock.json` from Peingxious's fork.

## Fixes that still apply

| Problem | Cause | Fix | Guarded by |
|---|---|---|---|
| The plugin never loaded on a fresh install, and a hand-edited or synced `data.json` of the wrong shape could stop it loading | Unvalidated `Object.assign` of saved data | `sanitizeSettings` validates every field and falls back to defaults; unknown keys are ignored | `settings.test.ts`, e2e |
| The first settings change was silently dropped, and one made just before quitting was lost | A startup hack skipped the first debounced save; the debounced save was never flushed on unload | Every real change persists; `onunload` closes the modal, then flushes the save and cancels the pending timers | e2e, `search-open-regressions.test.cjs` |
| Text typed right after opening the search could be overwritten | The delayed state re-apply ignored the input | It only re-applies while the input is untouched | `tests/`, e2e |
| The last search text was written to `data.json` in plaintext | The whole view state was saved | The query is never persisted or restored | `settings.test.ts`, e2e |
| Release builds were not reproducible or hardened, and releases left out `styles.css` | An old workflow ran `npm install`, used mutable action tags and uploaded only some files | bun with a frozen lockfile, SHA-pinned actions, release-please, attested `main.js`, `manifest.json` and `styles.css`, the full test run before publishing | CI, `release.test.ts` |
| Lint backlog (446 `eslint-plugin-obsidianmd` problems) and the community scorecard findings that lint missed | Obsidian internals reached through `any`; `:has()` and `!important` in CSS; licence text; advisories | Internals are typed, patches go through `monkey-around`, `LICENSE` is the unmodified GPL, overrides for two advisories; `eslint --max-warnings 0 .` passes | `bun run lint`, `tests/scorecard.test.cjs`, `bun audit` |

Fixes made after the plugin was narrowed:

- A closed modal stayed referenced by the plugin until the next open, and a file drag
  closed whichever modal was current 10 ms later. The reference is cleared on close and
  the drag handler closes only the modal that was open (e2e, regression test).
- The undo-history patch skipped every search view in the app; it now skips only the
  embedded one (`embedded-leaf.test.cjs`).
- Clicking a result while previewing resolved the file from its title text and picked
  the wrong note when two share a name; it now uses the clicked row (e2e).
- Shift+Tab closed the preview with half of what typing does, and its border class
  outlived it (e2e).
- Files that were only previewed were recorded as recent files, in Obsidian's own list
  and in the Recent Files plugin's. The inherited hook patched a method Obsidian no
  longer has, and the other half held for 1 ms. The recent-file tracker is now patched
  to skip a file only an embedded leaf showed, and the Recent Files plugin's
  `shouldAddFile` is wrapped while the modal is open (e2e against the real Recent Files
  plugin, installed disabled at a version Renovate maintains; node tests for both patches).
- Text typed in the instant before the delayed state was applied had its caret moved to
  the start, and a modal closed before the search view took its state saved the view's
  defaults over the remembered sort order and options. The selection is now left alone
  once the user has typed, and nothing is saved from a view that never took its state
  (node tests, an e2e test for the early close).
- When Obsidian failed to build the search view or open a preview, the modal was left
  half-built and the only trace was an unhandled rejection in the console. One helper
  now logs the cause and shows a notice; a failed build closes the modal and a failed
  preview removes its empty pane (e2e with forced failures, node tests).
- Selecting the canvas card a result matched read the canvas 1 ms after opening it and
  selected 20 ms later, so a canvas that took longer to load (or a reused leaf still
  holding the previous canvas) got no selection. It now selects after the awaited open,
  and only if the leaf still shows that file (e2e with slowed canvas reads, node tests).
- Enter, or Cmd+Enter, could open the result inside the preview instead of the
  workspace when Obsidian still counted the preview as the active leaf (e2e).
- After a plain arrow key Obsidian blurs the search input and focus stayed on the page
  body until the preview finished, so Enter or typing in that window went nowhere
  (e2e).
- Typing with a preview open lost every character after the first: detaching the
  preview leaf made Obsidian drop focus to the page. The input is refocused once the
  preview is cleared (e2e: a second search with a preview open, previewing one of its
  results, and checking the typed query reached the input).
- Reading mode only flashes the matched block, so the match disappeared once the flash
  faded. The matched text inside that block is now marked with the CSS Custom Highlight
  API until the preview changes or closes (`src/matchHighlight.ts`, unit tests, e2e).
- That highlight used `--text-highlight-bg`, which Obsidian does not define, so it
  computed to a transparent background and only Obsidian's own flash was visible. It
  now uses `--highlight-background` with a yellow fallback, and an e2e spec checks the
  highlight is actually painted.
- Obsidian was patched for the rest of the session after the first search, and two
  patches only served one call site each. The canvas card is now selected by the modal
  right after it awaits the preview's `openFile` (no `WorkspaceLeaf.openFile` patch),
  and the modal closes on a `dragstart` from a result row (no `DragManager` patch).
  The remaining patches are installed when a search opens and removed when it closes,
  and a patch that fails to install undoes the ones already applied (node tests, e2e
  against the real Obsidian).
- Closing the modal released the patches before it detached its leaves, so the search
  (query included) and the previewed note landed in Obsidian's closed-tab history. The
  leaves are detached first and the patches released last, and the undo-history patch
  now skips every embedded leaf, not only search views (node tests, e2e).
- Each inherited patch was removed in turn and the e2e suite run against the real
  Obsidian. Two had no observable effect and are gone: the `setPinned` guard and the
  `setActiveLeaf` wrapper that called `old` twice and set `activeTime = 1700000000000`
  (embedded leaves are not in the workspace's root split, so `getMostRecentLeaf` never
  returns them; an e2e spec now guards that). The leaves are no longer pinned when
  created either: with and without the pin, the full e2e suite behaves the same. Two
  patches are kept because removing them changed behavior: `getRoot` (the embedded
  leaves would no longer resolve to the workspace root) and `getLeaf` (a link clicked
  in the preview would open the note in a background tab of the workspace).
- The README used to say a link clicked in the preview replaces the previewed file.
  In Obsidian 1.15.1 it does nothing (the patched `getLeaf` returns the preview leaf,
  but the note is not opened in it), so the claim was dropped. The e2e
  spec guards that the click opens nothing in the workspace.
- The search box keys were one `onkeydown` switch of about 90 lines on the input, and
  Ctrl+N and Ctrl+P did nothing: the handler called `preventDefault` before forwarding
  the event, and Obsidian's own handler skips an event that is already prevented. The
  keys are now bound with the modal's `Scope` (one handler per key, forwarding to the
  search view), which fixes them. Handlers ignore events from outside the search box
  (the preview keeps its arrow keys) and while text is being composed. Ctrl+Shift+N and
  Ctrl+Shift+P no longer expand context; the documented Shift+Up and Shift+Down do.
  Left and Right are no longer forwarded to the search view (they did nothing visible
  with real key presses, and the README never documented them), so they move the caret
  as in any text field (e2e). The
  operator suggestion menu now gets its keys before the result navigation (e2e,
  `keys.e2e.ts`).

## Tooling decisions

- `minAppVersion` is **1.15.1** (was 1.13.0, 1.8.7, 1.5.7, originally 1.2.0): the search
  view's relevance sort, which is the default here, is first offered in 1.15.1 (1.13.4
  and 1.15.0 silently fall back to alphabetical). Earlier raises: `getLanguage()`
  (1.8.7) and declarative settings (`getSettingDefinitions()`, 1.13).
- Tests: unit tests (`bun test`, colocated), node regression tests in `tests/` that run
  the real source against small stand-ins for Obsidian (excluded from typed linting;
  see `tests/README.md`), and e2e specs in `test/specs/` that run the built plugin in a
  real Obsidian through `wdio-obsidian-service`. `bun run screenshot` retakes the README
  screenshot from `test/screenshots/` in its own vault.
- `bun run test:e2e:container` runs the e2e suite in a Linux container under a virtual
  display (Apple's `container`, Docker or Podman; `scripts/e2e-container.sh`,
  `test/container/`), so no Obsidian window opens on the developer's machine.
- The e2e tests install the Recent Files community plugin (disabled, pinned by
  `RECENT_FILES_VERSION` in `test/wdio.conf.mts`). A repo-local Renovate custom manager in
  `.renovaterc.json` reads that constant and bumps it from the plugin's GitHub releases.
- Package manager is bun and tools are pinned with mise (copied from Search Jump).
  Releases go through release-please and need the GitHub App secrets described in
  `CONTRIBUTING.md`.
- `main.js` is allow-listed in gitleaks (generated bundle, a tokenizer table looked like
  a key).

None recorded. The regex-denial-of-service risk belonged to the removed regex filter.

## Naming and releasing

- The plugin is named Search & Open (id `search-open`). The upstream id `float-search`
  and name "Floating Search" belong to the original listing, so this is a separate
  plugin. It was first named Floating Search Next (`floating-search-next`) and
  positioned as a successor, then Pane Search (`pane-search`), and was renamed once
  it narrowed to opening the file that matches a search. The GitHub repository was
  renamed to `hugoh/obsidian-search-open` at the same time (the old URL redirects).
- For now the plugin is not listed on the Obsidian Community site. It was listed under
  an earlier name and withdrawn; as a derivative it needs the original author's
  approval to be listed (see issue #13), so it is installed with BRAT until
  that is sorted out (see the README).
- Installing both at once conflicts (same patched internals, same `obsidian://fs`
  handler); the README advises against running them together.
- Settings are stored per plugin id, so users start fresh, including anyone who
  installed `floating-search-next` or `pane-search`; there is no automatic import.
- Versions started at 0.1.0 (the first release was forced with `release-as`, which
  has since been removed from `release-please-config.json`). While below 1.0,
  `bump-minor-pre-major` keeps breaking changes in the 0.x line.
- Differences from upstream 4.3.0 that users should know about: minimum Obsidian 1.15.1,
  the removal of most features (see the table above), and the new plugin id.
