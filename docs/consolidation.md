# Consolidation notes

This plugin brings the forks of [Quorafind/Obsidian-Float-Search](https://github.com/Quorafind/Obsidian-Float-Search)
together. This file records **where each feature came from** and **every fix made
while merging and cleaning up**, so the history does not have to be reverse
engineered from the commits. Keep it up to date when changing either.

The `CHANGELOG.md` is generated by release-please; this file is the human-written
provenance record.

> **Status.** Most of what is recorded below was later removed to narrow the plugin to
> the global search modal: the CMDK quick search and its query-syntax engine, saved
> searches, exclusions, the filter bar and regex mode, quick create, the split / tab /
> window / sidebar views, the operator commands, the `setState` re-route, the
> file-path display, and the editor and file context menu items. Entries that mention
> those are kept as provenance only. The modal, the embedded leaf, the i18n
> scaffolding and the lifecycle fixes remain. The history is in the repository.

## What remains, and from whom

Measured when the plugin was renamed Search & Open: each non-trivial source line
(`src/*.ts`, `styles.css`, ignoring whitespace and trailing punctuation) was matched
against the final upstream, AiurArtanis and Peingxious versions in the repository
history, in that order. About 1,380 lines were counted:

| Origin | Share | What it is |
|---|---|---|
| Upstream (Quorafind, latest) | 55% | The modal, the embedded search view and preview, key handling, Obsidian typings, most of `leafView.ts` (itself derived from hover-editor), most of the CSS |
| Written or reworked here | 36% | Settings, the plugin entry, `latestQueue.ts`, the lifecycle and caret handling, the rewritten tests |
| AiurArtanis | 8% | The typed `strings()` and zh-CN translation, the IME guard, parts of the modal and CSS; the regression test harness (`tests/harness.cjs`, about 95% theirs) |
| Peingxious | 1% | The highlight crash guard and applying the patches on first use |

A line counts as "written here" when it is not found verbatim, so reformatting and
renamed identifiers push the share up; treat the numbers as a rough guide, not an audit.

## Merge reconciliation decisions

Both forks rewrote the same CMDK code, so the merge was done by hand:

- **Search pipeline**: Peingxious's query engine and candidate cache, with Aiur's
  regex / match-case matcher (`matchAsSearchResult`), filter bar, IME guard and
  abort handling layered on top.
- **Settings**: Aiur's tabs, plus a new *Filters* tab for Peingxious's exclusions
  and saved searches.
- **Localization**: Aiur's typed `strings()` kept; Peingxious's `t()` dictionary was
  appended and is being folded into it.
- **Delayed native `setState`**: Peingxious removed it to avoid a second search;
  Aiur's tests rely on it to apply match-case, so it was restored.
- **CMDK debounce** (150ms, Peingxious) kept; one inherited test that assumed
  synchronous search was adjusted.
- **Tooling**: esbuild bumped to 0.28 (Peingxious), TypeScript to 5, bun + mise.

## Refactors (behaviour unchanged)

- `LatestQueue`: one "newest request wins" helper replaces two hand-rolled
  preview queues (`latestQueue.test.ts`).
- `CmdkResult` is a discriminated union with `ephemeralStateFor`; the `file: null as any`
  rows and the dead `saved` variants are gone (`cmdkResult.test.ts`).
- One i18n system: Peingxious's `t()` dictionary was folded into Aiur's typed
  `strings()` (`i18n.test.ts` checks both languages stay in step).
- `freeText` / `isPlainText` replace two copies of query text extraction.
- Dead code removed: `isFileExcluded`, `textMatches`, `openSearchWithQuery`,
  `patchedDomChildren`, the `normalizePath` wrapper methods, the legacy
  `filterButtons` migration.
- `floatSearchIndex.ts` (3,300 lines) was split into the plugin (about 1,370),
  `settingsTab.ts`, `nativeModal.ts`, `cmdkModal.ts` and `namePrompt.ts`.

## Test coverage added

- Unit (`bun test`, colocated): query parser and filter, regex/case matching,
  exclusions, regex safety, i18n.
- e2e (`wdio-obsidian-service`, real Obsidian, `test/specs/`): quick search,
  exclusions, saved searches, native search modal.

## Tooling decisions

- `minAppVersion` is **1.13.0** (was 1.8.7, 1.5.7, originally 1.2.0): the code uses `AbstractInputSuggest` (1.4.10),
  `Vault.getFolderByPath` (1.5.7), `getLanguage()` (1.8.7) and declarative settings (`getSettingDefinitions()`, 1.13).
- The legacy vm-based regression suite in `tests/` (plain CommonJS stubs) is excluded
  from typed linting (the scorecard may still report unsafe-call/member-access findings there); everything else, including the unit and e2e tests, is linted.
- Package manager is bun and tools are pinned with mise (copied from Search Jump).
  Releases go through release-please and need the GitHub App secrets described in
  `CONTRIBUTING.md`.
- `main.js` is allow-listed in gitleaks (generated bundle, a tokenizer table looked like a key).

## Accepted risks

- Regexes with overlapping alternations (for example `(a|aa)+`) are not detected by
  `safe-regex2` and can still hang the UI. Only a worker with a timeout would fix this
  completely; judged not worth the complexity (the user types the pattern, the classic
  class is blocked, and the native search has the same weakness). Documented in the README.

## Naming and releasing

- The plugin is named Search & Open (id `search-open`). The upstream id `float-search`
  and name "Floating Search" belong to the original listing, so this is a separate
  plugin. It was first named Floating Search Next (`floating-search-next`) and
  positioned as a successor, then Pane Search (`pane-search`), and was renamed once
  it narrowed to opening the file that matches a search. The GitHub repository is
  still `hugoh/obsidian-pane-search`.
- For now the plugin is not listed on the Obsidian Community site. Forks need the
  original author's approval to be listed, so it is installed with BRAT until that is
  sorted out (see the README).
- Installing both at once conflicts (same patched internals, same `obsidian://fs`
  handler); the README advises against running them together.
- Settings are stored per plugin id, so users start fresh, including anyone who
  installed `floating-search-next` or `pane-search`; there is no automatic import.
- Versions started at 0.1.0 (the first release was forced with `release-as`, which
  has since been removed from `release-please-config.json`). While below 1.0,
  `bump-minor-pre-major` keeps breaking changes in the 0.x line.
- Differences from upstream 4.3.0 that users should know about: minimum Obsidian 1.13.0,
  the removal of most features (see the status note above), and the new plugin id.
